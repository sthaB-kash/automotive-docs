    Vietwheels · rake listings:vw_csv_import

    VW listing import runbook

    Imports Chotot car listings from vw-data.xlsx (or a UTF-8 .csv) into Vietwheels. The code lives only on this page and is not committed to the repo. Copy the files to the server, restart Sidekiq, run the task in the background and check the logs.

    Server dev@13.236.189.248 App /home/dev/www/africar/vietwheels Queues listing_import, images Saved 28 Oct 2026, branch feat/vw-new-design
    vw-data.xlsx→ rake vw_csv_import→ VwRow validate→ VwListingImportWorker→ ListingImageWorker

    Bad rows never reach Sidekiq. They go to vw-data_invalid.csv. Each listing's source is vw_chotot_<chotot ad id>, so running the import again skips rows that are already in the database.

    Run on production

    This is the procedure used on production: copy the files over, restart Sidekiq with mina, run the rake task in the background and follow the logs.

    Before the first import only

    The listings.source index must exist. Check it once, and run db:migrate if it prints false. Optionally, add missing brands and models with scripts/update_brands_and_models.rb first. It does a dry run by default.

    cd /home/dev/www/africar/vietwheels/current
RAILS_ENV=production bundle exec rails runner 'p ActiveRecord::Base.connection.index_exists?(:listings, :source)'
RAILS_ENV=production bundle exec rake db:migrate

RAILS_ENV=production bundle exec rails console
load Rails.root.join('scripts/update_brands_and_models.rb').to_s
UpdateBrandsAndModels.call                   # dry run, read the report
UpdateBrandsAndModels.call(dry_run: false)   # apply

    1. Copy the required files

      Save the files from the Code section into your local checkout at the same paths, then copy them and the data file to the server from the project root. The code goes into current/, where the next mina deploy removes it. That's fine, because the code isn't committed. The data file goes into shared/.

      rsync -avR \
  lib/tasks/batch_upload.rake \
  app/services/listing_import/vw_row.rb \
  app/services/listing_import/xlsx_reader.rb \
  app/workers/vw_listing_import_worker.rb \
  app/workers/listing_image_worker.rb \
  db/migrate/20261016090000_add_index_to_listings_source.rb \
  dev@13.236.189.248:/home/dev/www/africar/vietwheels/current/

scp vw-data.xlsx dev@13.236.189.248:/home/dev/www/africar/vietwheels/shared/
      • .xlsx is the safest format. A .csv must be UTF-8. If Excel saved it as Windows-1252, the task stops, because the Vietnamese characters are already lost.
      • Columns it reads: title, body, make, model, year, mileage, number_of_seats, price, area, region, post_by, fuel_type, gearbox, url, phone_number, image1_url, image2_url, image3_url, image3_url_1.

    2. Restart Sidekiq

      Run this from your machine. The restart loads the new worker classes. sidekiq:start uses the flags in your local config/deploy.rb, so that file must include -q images -q listing_import. Without those flags the import jobs never run. The excerpt is in the Code section.

      mina sidekiq:stop && mina sidekiq:start

# check on the server: the command line should list both queues
ssh dev@13.236.189.248 'ps aux | grep [s]idekiq'

      Monit or systemd. If Monit or a systemd unit (sidekiq-vietwheels.service) also restarts Sidekiq, add the two queues to that config too. Otherwise an automatic restart drops them.

    3. Run the rake task in the background

      nohup keeps the task running after you log out. Its terminal output goes to log/vw_csv_import_rake.log.

      ssh dev@13.236.189.248
cd /home/dev/www/africar/vietwheels/current

RAILS_ENV=production FILE=/home/dev/www/africar/vietwheels/shared/vw-data.xlsx \
  nohup bundle exec rake listings:vw_csv_import > log/vw_csv_import_rake.log 2>&1 &

# is it still running?
ps aux | grep [v]w_csv_import

      To check the file first without enqueuing anything, run the same command with DRY_RUN=1 in front, then read the summary and shared/vw-data_invalid.csv.

      The task waits whenever listing_import has 20 or more jobs, so lines like Queue size 20 >= 20, waiting 10s... are normal. It finishes once every batch is enqueued. The workers keep running after that.

    4. Check the logs

      cd /home/dev/www/africar/vietwheels/current
tail -f log/vw_csv_import_rake.log   # rake output: summary, queue waits, "Enqueued N batches"
tail -f log/vw_import.log            # worker: Imported x/y, skipped rows
tail -f 0carpla_image-upload-err.log # failed image downloads

# queue sizes, retries and dead jobs
RAILS_ENV=production bundle exec rails runner '
  %w[listing_import images].each { |q| puts "#{q}: #{Sidekiq::Queue.new(q).size}" }
  puts "retries: #{Sidekiq::RetrySet.new.size} | dead: #{Sidekiq::DeadSet.new.size}"
  puts "imported: #{VehicleListing.where("source LIKE ?", "vw_chotot%").count}"'

      Images download 30 to 120 seconds after each batch, so photos show up on listings a little later than the listings themselves.

    5. Finish up

      The worker bulk-inserts listings and skips model callbacks. If the multi-fuel listing_fuels table is on production, fill it in for the new listings. Otherwise they don't show up when someone filters by fuel. The insert is safe to run more than once.

      RAILS_ENV=production bundle exec rails runner '
  if ActiveRecord::Base.connection.table_exists?(:listing_fuels)
    n = ActiveRecord::Base.connection.exec_update(<<~SQL)
    INSERT INTO listing_fuels (listing_id, fuel_id, created_at, updated_at)
    SELECT l.id, l.fuel_id, NOW(), NOW() FROM listings l
    WHERE l.source LIKE $$vw_chotot%$$ AND l.fuel_id IS NOT NULL
      AND NOT EXISTS (SELECT 1 FROM listing_fuels lf WHERE lf.listing_id = l.id AND lf.fuel_id = l.fuel_id)
  SQL
    puts "listing_fuels added: #{n}"
  else
    puts "no listing_fuels table, nothing to do"
  end'

# refresh home page counts and filters
RAILS_ENV=production bundle exec rails runner "Rails.cache.clear"

      If you used Option A, the copied files go away on the next deploy. Nothing else needs cleaning up.

    Task options

    Set these as environment variables in front of the rake command.

    VariableDefaultEffect
    FILE (or CSV)vw-data.xlsxInput file. Relative paths start from the app root. An absolute path is used as given.
    DRY_RUNoffValidate and write the rejects file only. Nothing is enqueued.
    BATCH_SIZE100Rows per VwListingImportWorker job.
    MAX_QUEUE20Pause enqueuing while listing_import holds this many jobs.
    ALLOW_LOSSY_ENCODINGoffImport a Windows-1252 CSV anyway. The Vietnamese text comes out as ?. Avoid it.

    Troubleshooting

    SymptomCause and fix
    Task stops with is not UTF-8Excel saved the CSV as Windows-1252. Use the .xlsx or export the CSV again as UTF-8.
    Queue keeps growing, vw_import.log stays quietSidekiq isn't listening on listing_import, or it wasn't restarted after the files were copied. Go back to step 2.
    Row N skipped — no city_idThe region couldn't be created. On dev the error was Name bn can't be blank because Region needs every translated name. Create the region by hand, then run the import again.
    Region or title shows ? in place of Vietnamese lettersThe file was imported with the wrong encoding. Remove those listings (see Undo), fix the file and run again.
    Listings with no photosCheck 0carpla_image-upload-err.log. Chotot image URLs expire, so re-export the data if most of them fail.
    Skipped N already importedExpected on a second run. Rows are matched on source.

    Undo an import

    This can't be undone. Back up the database first (mina backup). This deletes every listing imported from Chotot, including its pictures and phone numbers. Seller users created by the import are kept.

    RAILS_ENV=production bundle exec rails runner '
  scope = VehicleListing.where("source LIKE ?", "vw_chotot%")
  puts "deleting #{scope.count}"
  scope.find_each(&:destroy)'

    Code

    Click ▾ in the gutter to fold a block. Folded blocks show ↔; click it to open them again. Copy places the whole file on the clipboard.

    Rake task

    lib/tasks/batch_upload.rake

    Only the vw_csv_import task and its helpers. Reads the file, validates every row, writes rejects to <file>_invalid.csv and enqueues valid rows in batches.

    Row validator

    app/services/listing_import/vw_row.rb

    Pure Ruby, no DB access. Parses and validates one row and builds the compact Sidekiq payload.

    XLSX reader

    app/services/listing_import/xlsx_reader.rb

    Streams the first worksheet with rubyzip + Nokogiri SAX. No extra gem needed.

    Import worker

    app/workers/vw_listing_import_worker.rb

    Queue listing_import. Resolves users, brands, models and cities, bulk-inserts listings and phone numbers, then schedules image downloads. Logs to log/vw_import.log.

    Image worker

    app/workers/listing_image_worker.rb

    Queue images. Downloads each image URL into a Picture. Failures go to 0carpla_image-upload-err.log.

    Migration

    db/migrate/20261016090000_add_index_to_listings_source.rb

    Index on listings.source, built concurrently. Every batch looks up already-imported rows by source.

    Deploy change (excerpt)

    config/deploy.rb

    Not the whole file. Only the Sidekiq queue flags the import needs.

    Catalogue prep (optional)

    scripts/update_brands_and_models.rb

    Creates missing brands and models before an import. Dry run by default.
